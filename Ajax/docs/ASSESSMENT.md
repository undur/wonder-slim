# Ajax framework — assessment
_Opinionated analysis of the wonder-slim `Ajax` framework, companion to the neutral overview page in AjaxPlayground. Every element is scored on **two independent axes**, deliberately kept separate._

## The two axes

The earlier single-badge version conflated these and wrongly tagged core primitives (e.g. `AjaxHyperlink`) as "avoid" merely because they run on Prototype. They are now scored separately:

- **Status** — _what should I reach for, using the framework as it is today?_ Judges the **capability and centrality only**; the implementation tech is irrelevant here. A primitive built on Prototype can still be `Core`.
  - 🟩 **Core** — a primary, load-bearing way to interface with the framework; most non-trivial apps use it.
  - 🟦 **Useful** — a solid, commonly-reached-for capability, but not foundational.
  - ⬜ **Niche** — valid but special-purpose / rarely needed.
  - 🟥 **Dead** — broken at runtime, or the capability itself is obsolete.
- **Modernization** — _the engineering debt / cleanup direction._ Judges the **implementation only**.
  - ✅ **Modern** — already dependency-free / morph-native; no rewrite needed.
  - 🔧 **Needs rewrite** — keep the element + its server contract; move the client off Prototype onto fetch()+morph.
  - 🌐 **Replace with platform** — the browser now does this natively (`<dialog>`, `<details>`, `<input type=…>`, CSS, Popover); retire in favor of the platform.
  - 🗑️ **Delete** — remove outright (broken, or dead weight).

The headline consequence: **a `Core` element can be `Needs rewrite`** — that means "use it, it's fundamental; and separately, its client is slated for a fetch rewrite." That is the common case for this framework's spine.

## Per-element verdicts

### 🟩 Core (12)

**Ajax** — 🟩 Core / ✅ Modern  
_Role._ Framework principal that boots the Ajax framework at app launch, registering the AjaxRequestHandler, the comet/push handler, and the AjaxResponse delegate.  
_Status._ Framework principal that boots the entire Ajax stack at launch (registers the ajax request handler, the comet/push handler, the AjaxResponse double-click-recovery delegate). Nothing in the framework functions without it; every app that uses any Ajax element relies on it being installed.  
_Modernization._ Pure server-side bootstrap with no client JS of its own. It registers handlers and a delegate; none of that is Prototype-coupled. It survives a fetch()+idiomorph migration unchanged, so no rewrite is needed. (The JS it indirectly governs lives in the elements, not here.)
**AjaxFileUploadRequestHandler** — 🟩 Core / ✅ Modern  
_Role._ A WORequestHandler registered under the 'upload' key that consumes the multipart upload request out-of-band, streams the body to a temp file while tracking progress (AjaxUploadProgress), enforces a max-upload-size, and restores the session by id so the upload can run without blocking the session lock.  
_Status._ This is the load-bearing server-side engine that makes non-blocking Ajax uploads possible at all: it consumes the multipart request out-of-band, streams to a temp file while tracking progress, enforces max-upload-size, and restores the session by id so the upload runs without holding the session lock. Both upload components are non-functional without it, so within the file-upload capability it is the essential primitive.  
_Modernization._ Pure server-side Java (WOMultipartIterator, ERXUnitAwareDecimalFormat, ERXProperties, AjaxUploadProgress) with no client JS and zero Prototype/Scriptaculous dependency. It is framework-agnostic on the wire — a rewritten fetch()-based client can POST multipart to the same 'upload' request-handler key unchanged — so it needs no rewrite, only its sibling clients do.
**AjaxRequestHandler** — 🟩 Core / ✅ Modern  
_Role._ WOComponentRequestHandler subclass registered under the 'ajax' key so Ajax component actions get a dedicated URL namespace and page-storage is suppressed for them.  
_Status._ WOComponentRequestHandler registered under the 'ajax' key, giving Ajax component actions a dedicated URL namespace and suppressing page storage for them. This URL-routing/page-store behavior underpins how every Ajax component action is dispatched; foundational plumbing.  
_Modernization._ Pure server-side request handler with no client JS and no Prototype coupling — it only routes URLs and calls enableShouldNotStorePage. A fetch()+idiomorph client still posts to this same 'ajax' namespace, so the handler is reusable as-is with no rewrite.
**AjaxComponent** — 🟩 Core / 🔧 Needs rewrite  
_Role._ Abstract WOComponent base for stateful (.wo) Ajax components, wiring up request handling, binding helpers, and resource-injection convenience methods.  
_Status._ Abstract base for all stateful (.wo) Ajax components, wiring the request-dispatch contract (shouldHandleRequest/handleRequest/invokeAction) and binding/resource helpers. Sibling of AjaxDynamicElement; foundational to building any Ajax component.  
_Modernization._ The server-side dispatch contract is worth keeping, but its resource-injection helpers exist to push the Prototype-based Ajax JS into the head, and its whole reason for being is the legacy Ajax client model. As the client moves to fetch()+morph, the base class's resource/dispatch plumbing must be reworked to emit/serve the new client rather than the Prototype stack. Keep the contract, rewrite the client coupling.
**AjaxDynamicElement** — 🟩 Core / 🔧 Needs rewrite  
_Role._ Abstract WODynamicElement base for stateless Ajax elements (most er.ajax elements extend this), providing the same request-dispatch and resource-injection contract as AjaxComponent.  
_Status._ Abstract base for nearly all stateless er.ajax elements, providing the identical request-dispatch and resource-injection contract as AjaxComponent. Sibling base class; load-bearing for the framework. Scored identically to AjaxComponent per the consistency rule.  
_Modernization._ Same situation as AjaxComponent: keep the server-side dispatch/handleRequest contract, but the addRequiredWebResources/resource-injection plumbing exists to wire up the Prototype client and must be reworked for the fetch()+idiomorph client. Scored identically to its sibling.
**AjaxHyperlink** — 🟩 Core / 🔧 Needs rewrite  
_Role._ An anchor (or arbitrary element) that fires a background Ajax.Request to a server action on click and runs JS callbacks (onSuccess/onFailure/onComplete) with the response, optionally rendering itself as a named JS function instead of a link.  
_Status._ A link/element that fires a server action in the background and runs client callbacks (onSuccess/onFailure/onComplete) is one of the foundational ways to drive partial interactivity in this framework; most non-trivial apps reach for it. The functionName mode (render as a callable JS function) further makes it a general-purpose trigger.  
_Modernization._ Client emits `new Ajax.Request(...)` and force-loads prototype.js + effects.js in addRequiredWebResources; the server action contract is worth keeping but the onClick generation must move from Prototype's Ajax.Request to fetch()+idiomorph.  
_Target._ Keep handleRequest/server action; regenerate onClick to a fetch() call, drop prototype.js/effects.js.
**AjaxObserveField** — 🟩 Core / 🔧 Needs rewrite  
_Role._ Watches a form field (or all descendant fields) for value changes and fires an Ajax partial submit + optional container update, i.e. live/auto-submit-on-change without a visible button.  
_Status._ The live/auto-submit-on-change primitive: watches a field (or all descendant fields) and fires a partial submit plus optional container update with no visible button. This is a primary, commonly-used way to build reactive Ajax forms.  
_Modernization._ Keep the capability and its submit-name/partial-submit server contract, but the client emits ASB.observeField / ASB.observeDescendentFields in wonder.js, which wrap Prototype's Form.Element.Observer and reuse the ASB submit machinery and Form.serialize. Move to native input/change event listeners + fetch()+idiomorph (the platform's change event plus FormData replaces the Prototype observer).
**AjaxResponse** — 🟩 Core / 🔧 Needs rewrite  
_Role._ WOResponse subclass that runs a second 'update pass' so an Ajax action can render one or more AjaxUpdateContainers in the same response, plus a delegate that recovers from double-click/null-result race conditions.  
_Status._ WOResponse subclass implementing the second update-pass that lets one ajax action render one or more AjaxUpdateContainers in a single response, plus the AjaxResponseDelegate that recovers from double-click/null-result races. This is the backbone of the partial-update model that most Ajax apps depend on.  
_Modernization._ The update-pass mechanism and the null-result/double-click recovery are valuable server-side contract worth preserving, but updateDomElement emits Prototype's Element.update() and the response is shaped for the Prototype client (script header/footer, content-type juggling). The client-facing emission must move to fetch()+idiomorph while the update-pass machinery is retained.
**AjaxSubmitButton** — 🟩 Core / 🔧 Needs rewrite  
_Role._ A WOSubmitButton replacement that submits its form in the background via Ajax (serializing the form, optionally partial-submit) and updates a container/replace region with the result; the workhorse for Ajax form submission.  
_Status._ The workhorse for Ajax form submission: a WOSubmitButton replacement that serializes and submits the form in the background (full or partial submit) and updates a container/replace region. Foundational for any app doing Ajax forms.  
_Modernization._ Keep the element and its ERXAjaxApplication coordination (AJAX_SUBMIT_BUTTON_NAME, partial-sender key, replaceID/updateContainerID contract). But the client is Prototype: ASB.update/ASB.request in wonder.js built on Ajax.Request and Form.serializeWithoutSubmits, with Scriptaculous Effect.* for effects. Rewrite onto FormData + fetch()+idiomorph; drop the effect bindings.
**AjaxUpdateContainer** — 🟩 Core / 🔧 Needs rewrite  
_Role._ Renders a named DOM region (a div by default) that can be re-rendered in place via an Ajax round-trip, optionally on a timer or driven by an observed field; the foundational element every other Ajax partial-update component targets.  
_Status._ The foundational partial-update primitive: it renders the named, re-renderable DOM region that every other Ajax component targets. Supports action refresh, periodic/timer refresh, and observe-field-driven refresh. Virtually every non-trivial Ajax app uses it; it is the single most load-bearing element in the framework.  
_Modernization._ The server contract (named region carrying data-updateUrl + data-morph, re-rendered via component action) is exactly what should be preserved, and idiomorph is already wired in for the content-reconciliation step. But the client driver is still Prototype's Ajax.Updater plus AUC.* helpers in wonder.js, periodic mode uses Prototype's PeriodicalExecuter, and insertion shortcuts map to Scriptaculous Effect.PAIRS. Keep the element and its contract; move the client off Prototype/Scriptaculous onto fetch()+idiomorph (morph already half-done).
**AjaxUpdateLink** — 🟩 Core / 🔧 Needs rewrite  
_Role._ Renders an anchor (or button/JS function) whose click fires an Ajax action and refreshes a target AjaxUpdateContainer (or replaceID region), i.e. the standard 'click to update part of the page' link.  
_Status._ The standard 'click a link to update part of the page' element, targeting an AjaxUpdateContainer or replaceID region. Together with the update container it is the canonical partial-update interaction most apps reach for first.  
_Modernization._ Keep the element and its server action contract, but the emitted onclick is Prototype: AUL.update(...) fast path, or raw new Ajax.Request / new Ajax.Updater, with Scriptaculous new Effect.Xxx for effects/insertion. The client must move to fetch()+idiomorph; the effect bindings should be dropped or re-expressed in CSS during the rewrite.
**AjaxUtils** — 🟩 Core / 🔧 Needs rewrite  
_Role._ Central static utility grab-bag for the Ajax framework: building AjaxResponses, injecting script/CSS resources, JS-string quoting/escaping, request-routing decisions, array/JSON coercion, and DOM-update JS emission.  
_Status._ Central static utility used pervasively across the framework: createResponse, shouldHandleRequest routing, script/CSS resource injection, JS quoting/escaping/jsSafeIdentifier, ajaxComponentActionUrl, array/JSON coercion. Effectively every Ajax element calls into it; it is foundational plumbing.  
_Modernization._ Mostly platform-neutral server plumbing, but it is the framework's seam to the Prototype client: updateDomElement emits Prototype's Element.update(), jsSafeIdentifier must stay in lockstep with ajaxSafeName() in wonder.js, and the script header/footer + resource injection serve the Prototype stack. The DOM-emission and client-coupled helpers must be rewritten to target idiomorph; the routing/response helpers can largely stay. Keep the class, rewrite the Prototype-emitting parts.

**AjaxPopUpButton** — 🟦 Useful / ✅ Modern  
_Role._ A drop-in WOPopUpButton subclass that renders a searchable, morph-native single-select (the wonder-select custom element) instead of a bare `<select>`; reach for it when a long option list needs type-to-filter.

**IAjaxElement** — 🟦 Useful / ✅ Modern

**AjaxBusySpinner** — 🟦 Useful / 🔧 Needs rewrite

**AjaxExpansion** — 🟦 Useful / 🔧 Needs rewrite

_Status._ A single disclosure/expander whose toggle fires a server action and Ajax-updates only the inline content area (not the link), adding an 'expanded' class for icon styling. A genuinely useful expand-with-server-roundtrip widget, commonly reached for but not a foundational primitive.  
_Modernization._ Although a pure client-side disclosure is now native `<details>`/`<summary>`, this element's real value is the server action fired on toggle plus the partial content update; it is composed of AjaxUpdateLink/AjaxUpdateContainer and carries Prototype + Scriptaculous (effects.js for the blind animation) + wonder.js. _Modernization._ Both axes point to removal: the client is a hard Scriptaculous dependency (addRequiredWebResources injects prototype.js/effects.js/dragdrop.js; template calls Sortable.create/Sortable.serialize/Ajax.Request and every effect binding maps to Scriptaculous Effect.*), and the server reorder logic is already broken/stubbed out. There is no working contract to preserve. If list reordering is wanted later it should be reimplemented fresh on the native HTML Drag-and-Drop API + fetch()+idiomorph rather than rewired.
**AjaxRoundEffect** — 🟥 Dead / 🌐 Replace w/ platform  
_Role._ An AjaxDynamicElement that applies the Rico library's Rico.Effect.Round to give an element CSS-less rounded corners by drawing them in JavaScript; devs reached for it in the pre-border-radius era to round box corners.  
_Status._ Draws CSS-less rounded corners by painting them in JavaScript, a pre-border-radius (2006-2008) workaround. Already @Deprecated in source; the capability itself is obsolete today and nobody should reach for it.  
_Modernization._ Built on prototype.js + rico.js (Rico.Effect.Round). CSS border-radius has done this natively across all browsers for over a decade, so the element should be retired in favor of the platform (effectively delete-and-use-CSS).  
_Target._ Delete; replace usage with the CSS border-radius property.
**AjaxSocialNetwork** — 🟥 Dead / 🌐 Replace w/ platform  
_Role._ An abstract server-side registry/factory of ~19 hardcoded social-bookmarking sites (del.icio.us, Digg, Furl, StumbleUpon, etc.) that each build a 'submit this URL+title' share link for the given page.  
_Status._ A hardcoded registry of ~19 social-bookmarking sites (del.icio.us, Furl, StumbleUpon, Squidoo, Magnolia, Spurl, Tagtooga, Newsvine, etc.) that are almost all defunct. The capability itself — share-to-bookmarking-site link builders — is obsolete; nobody should reach for this today (note even the Technorati URL is typo'd 'ttp://').  
_Modernization._ Pure server-side Java with no Prototype dependency, so it's not a JS-tech problem. But the whole thing is superseded by the platform: navigator.share (Web Share API) plus a couple of still-live intent URLs cover real sharing today. Retire the bundled-icon registry in favor of the platform.
**AjaxSocialNetworkLink** — 🟥 Dead / 🌐 Replace w/ platform  
_Role._ A component that renders a hyperlink (wrapping the network's bundled icon image) to a social network's share/submit URL for a given page URL and title.  
_Status._ Renders an `<a>``<img>``</a>` to a social network's share URL, driven entirely by AjaxSocialNetwork's mostly-defunct site list. Same obsolete capability as its data source — sharing to dead bookmarking services — so it is DEAD for the same reason; siblings kept consistent.  
_Modernization._ Plain server-rendered link/image with no JS or Prototype, but the sharing capability it delivers is now handled natively by navigator.share (Web Share API) / live share-intent URLs. Retire it together with AjaxSocialNetwork in favor of the platform.
**AjaxTextHinter** — 🟥 Dead / 🌐 Replace w/ platform  
_Role._ A wrapper element that turns an input's `default` binding into ghosted placeholder text, and re-registers forms/inputs after an Ajax refresh so the hints persist inside AjaxUpdateContainers.  
_Status._ Ghosts an input's default value as placeholder hint text. The capability itself is obsolete — every browser has had the native placeholder attribute for over a decade, so nobody should reach for this today.  
_Modernization._ Built on Prototype (Event.observe + AjaxHintedText in wonder.js), but the right move isn't a rewrite: the native HTML placeholder attribute does exactly this with zero JS. Retire in favor of the platform.
## Cross-cutting themes

- Prototype/Scriptaculous dependency rot is the dominant theme: roughly 35+ of the 72 elements hard-load prototype.js and/or effects.js/controls.js/dragdrop.js, and several pull in additional abandoned libs (Rico ~90KB, iBox, ModalBox, behaviour.js 2005, spin.js, ajaxupload.js, calendar.js/date.js, jabsorb 1.2.2). All of these are unmaintained dead-ends with no upgrade path — modernization means removal, not version bumps.
- Web-platform supersession: a large class of widgets reimplement in 2008-era JS what the browser now does natively — `<dialog>`/showModal (AjaxModalContainer, AjaxModalDialog), `<details>`/`<summary>` with name= (AjaxAccordion, AjaxToggleLink, AjaxExpansion), `<input type=date/range/file>` (AjaxDatePicker, AjaxSlider, file-upload family), placeholder (AjaxTextHinter), `<input type=reset>` (AjaxResetButton), CSS border-radius (AjaxRoundEffect), CSS @keyframes (AjaxHighlight, busy spinners), Popover API + CSS anchor positioning (AjaxHoverable), navigator.share (social), and querySelectorAll+addEventListener delegation (AjaxBehaviour).
- DOM-morph compatibility is the fault line that sorts winners from losers: morph is now the default, and the elements that fight it are flagged by their own data-morph-ignore hacks (AjaxModalContainer, AjaxSlider, AjaxAccordion, AjaxDraggable, AjaxFlexibleFileUpload) or by inline-`<script>` re-injection that doesn't re-run under idiomorph (FocusText/Field, AjaxHighlight, AjaxBehaviour, AjaxHoverable, the *Hinter). Conversely the morph-native custom-element approach (AjaxPopUpButton/AjaxBrowser) survives morph with zero re-init, which is the whole point.
- Inline-script-string generation is a pervasive anti-pattern: many elements emit hand-concatenated onclick='new Ajax.Updater(...)' / Effect.* / Behaviour.register(...) strings and global functions named by convention (`<containerID>`Edit()). This is fragile, un-CSP-friendly, pollutes the global namespace, and is exactly what breaks under morph. The modern direction is data-attributes + delegated listeners read by a small JS runtime.
- A healthy server/client seam already exists and should be the template for the rewrite: pure-Java models and SPIs (AjaxTreeModel, AjaxProgress/AjaxUploadProgress, AjaxResponseAppender, AjaxFileUploadRequestHandler streaming core, AjaxOption/AjaxConstantOption, the In-Place view/edit templates) carry the real value and have zero client coupling. Refactors should preserve these contracts and swap only the transport.
- Security and dead-data liabilities cluster in two spots: the jabsorb/AjaxProxy JSON-RPC stack exposes every public method by default (application.terminate reachable from the browser) on an unmaintained 2007 library, and AjaxSocialNetwork hardcodes ~19 mostly-defunct bookmarking services (del.icio.us, Furl, StumbleUpon, even a typo'd 'ttp://technorati.com' URL that was never exercised).
- Detection is stuck in the Prototype era: ERXAjaxApplication.isAjaxRequest keys solely on the x-requested-with:XMLHttpRequest header, which fetch()/custom elements do not send by default — so any modern (wonder-select-style) client must manually set it. Broadening this detection is the single highest-leverage substrate change for the modernization campaign.

## The dominant fact: Prototype/Scriptaculous rot

Massive and load-bearing on the client, near-zero on the server. Roughly 35+ of the 72 elements hard-load prototype.js, and a large subset additionally pull Scriptaculous (effects.js, controls.js, dragdrop.js, slider.js, builder.js) plus other dead libs (Rico ~90KB, iBox, ModalBox, behaviour.js, spin.js, ajaxupload.js, calendar.js/date.js, jabsorb). Every client-facing interaction primitive — Ajax.Updater/Ajax.Request transport, Form.Element.Observer field watching, Form.serialize, Effect.* animations, Sortable/Draggable/Droppable, Ajax.Responder busy-state, PeriodicalUpdater polling, $/$$/$wi DOM helpers — routes through Prototype. The critical implication: this is NOT upgradeable; Prototype and Scriptaculous have been dead since ~2010 and there is no compatible successor. Modernization is necessarily deletion-and-rewrite, and it must be coordinated because the transport is shared: AjaxUpdateContainer's fetch()+idiomorph rewrite is the keystone — almost every REFACTOR element (links, triggers, submit buttons, observe-field, in-place, tree, ping, progress) can only shed Prototype once the container exposes a Prototype-free update path. The good news is that the server side carries essentially none of this rot (AjaxOption/AjaxValue emit JS strings but load no client lib), so the WO contract survives the client purge intact. The proof of viability already ships: wonder-select (AjaxPopUpButton/AjaxBrowser) demonstrates a Prototype-free, morph-native widget working in production. Sequence the cull as: (1) fetch()+morph transport in AUC, (2) migrate the update/submit cluster onto it, (3) delete the platform-superseded widgets outright, (4) rebuild the few genuinely-unique widgets (tree, selection-list, modal, file-upload, in-place) as wonder-select-style custom elements, (5) drop the bundled libraries and broaden isAjaxRequest detection in the substrate.

## Infrastructure layers

### Layer 2 — jabsorb / JSON-RPC bridge

Vendored cruft frozen in time and a security liability. jabsorb 1.2.2 is circa 2007-08, dead, and the pom carries a FIXME that it is not in Maven Central (resolves only from a local m2 copy bundled into the woa). Two classes are forked into the tree as patched copies, so it is a partial fork, not a clean upgradeable dep; the AjaxProxy TODO to move to 1.3.2 is ~15 years stale. Core anti-pattern: reflection RPC exports every public method of a registered object. AjaxProxy javadoc warns that without a proxy binding it exposes the whole parent component, making valueForKeyPath like application.terminate reachable from an untrusted browser, and it only warns rather than refusing; JSONComponent only guard is a hand-written checkAccess the dev must remember. Allow-by-default remote method invocation should not exist in 2026. Obsolete versus a plain fetch to a WODirectAction or component action returning JSON: explicit auditable surface, no reflective exposure, no dead library, no 16-year-old JS client. Recommendation: delete or quarantine, do not modernize. Drop the whole org.jabsorb plus er.ajax.json stack and the JAR from the slim release. Only blocker is AjaxProxy via AjaxFlexibleFileUpload and any app code using AjaxProxy/JSONComponent endpoints. Steps: audit downstream usage; replace the one FlexibleFileUpload call site with a direct JSON action and delete the layer; if it must stay short-term, make the proxy binding mandatory and document JSONComponent without checkAccess as unsafe. Do not upgrade jabsorb to 1.3.x. Aligns with the existing Ajax cleanup campaign.

### Layer 3 — ERExtensions Ajax substrate (ERXAjaxApplication/Session/Context)

Still necessary and architecturally sound FOR AS LONG AS the er.ajax framework (AjaxUpdateContainer et al.) is in use — which, per the project's own memory notes, it very much is (wonder-select, AjaxUpdateContainer morphing, AjaxPlayground are all active work). This trio is the load-bearing foundation under all of that: without ERXAjaxSession's replacement cache, component-action links inside Ajax-updated regions break with backtrack errors; without ERXAjaxApplication's null-result handling and the response delegate, AjaxResponse can't return partial updates; without ERXAjaxContext, partial form submits take values on the wrong forms. So this is NOT vendored cruft you can delete — it is the actual contract between ERExtensions and the Ajax module, and the design (string-key/header-based decoupling + a single delegate, zero compile dependency on er.ajax) is genuinely clean and worth preserving.

That said, several things are clearly dated and are good modernization targets rather than deletions:
1. Detection is fragile/legacy. isAjaxRequest keys solely on x-requested-with:XMLHttpRequest, a Prototype/jQuery-era convention that fetch()/modern code does not send by default. Anything modern (your own wonder-select custom elements) won't be seen as Ajax unless it manually sets that header. This is the single most consequential dated assumption in the layer.
2. On-demand resource loading (AOD.loadScript/loadCSS in ERXResponseRewriter) and Prototype-style URL markers (_u/_r/ismap '#') are Prototype-framework baggage. If the morph-default / wonder-select campaign succeeds in retiring Prototype-based AjaxUpdateContainer internals, the loadOnDemand path and the ismap-coords takeValues hack become dead weight.
3. ERXAjaxSession reimplements WO private internals (ERXPrivateKVC reflection into _subcomponents, _PermanentCacheSingleton, overriding _saveCurrentPage) — brittle against any WO runtime change and the highest-maintenance-risk code in the layer. It's the thing most likely to bite under a WO/JDK upgrade. Worth isolating/testing carefully.
4. The string-keyed header/userInfo protocol and the thread-local contextDictionary flag passing are clever-but-implicit; they're the kind of thing that's hard to follow precisely because there's no compile-time link. Fine to keep, but document the contract.

Net: keep it, treat it as the stable substrate, but when the Ajax modernization (morph-default, drop AjaxSlim, wonder-select) lands, this layer is exactly where you'll want to (a) broaden/replace isAjaxRequest detection and (b) prune the Prototype-era on-demand-loading and ismap paths. Verdict SOLID, with a DATED detection/loader surface flagged for the upcoming Ajax cleanup.

## Recommended modernization sequence

> **⚠ BLOCKER — decide the binding-compatibility contract first.** The Prototype/Scriptaculous
> dependency is exposed as ~63 **public bindings** (effects, insertion, and — critically — the
> Prototype callback surface: `onComplete`/`onSuccess`/`onFailure`/`evalScripts`/`asynchronous`/
> `frequency`/…) that real app templates depend on. Rewriting the client off Prototype silently
> changes or removes those binding semantics. Do **not** start step 1 below until the contract is
> decided. See [PROTOTYPE_REMOVAL_BLOCKER.md](PROTOTYPE_REMOVAL_BLOCKER.md) — it needs a real-world
> usage audit, then a stance (keep-callbacks-drop-effects / full shim / clean break).

The client transport is shared, so order matters:

1. **fetch()+morph transport in `AjaxUpdateContainer`** — the keystone; nothing else sheds Prototype until the container has a Prototype-free update path.
2. **Migrate the rest of the Core spine** onto it (UpdateLink, UpdateTrigger, ObserveField, SubmitButton, Hyperlink).
3. **Retire the platform-superseded widgets** (the 🌐 Replace-with-platform set) in favor of native elements.
4. **Rebuild the genuinely-unique widgets** (tree, selection-list, modal, file-upload, in-place) as wonder-select-style custom elements.
5. **Drop bundled libs** + broaden `ERXAjaxApplication.isAjaxRequest` beyond the `x-requested-with` header (it currently misses fetch()/custom-element clients — the single highest-leverage substrate fix).
